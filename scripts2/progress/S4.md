# S4 — Condition: Slippery Floor

Issue: #27 · Branch: `sprint/soup-mvp` · Status: **shipped**

## What shipped

Tokens are displaced vertically in bands with slight rotation, so the return
sweep to the left margin lands on the wrong line. `Line guide` stabilises them.

## Decisions taken

- **Banded, not per-word.** True per-line offsets would need layout knowledge —
  where the browser breaks a line depends on viewport width, which the pure core
  cannot know. Chunking tokens into bands of `tokensPerBand` (5) and sharing an
  offset across each band produces the same phenomenon — text sitting at
  inconsistent heights — without the core knowing anything about layout.
  Per-token jitter was rejected: a wavy baseline within a line is a different
  effect from line-level displacement, and it is the latter that destroys the
  return sweep.
- **Static, computed once.** `render.drift` is false by default and is forced
  false under `prefers-reduced-motion` even when the constant is on. Continuous
  motion is a vestibular hazard and there is no way to ask about motion
  sensitivity on a join screen without outing people.
- **Seeded randomness via `src/core/random.js`** (mulberry32). The purity gate
  bans `Math.random` in the core, so the seed arrives on the event. The session
  seed is set at `START_SOLO` and each round derives `seed + roundIndex * 101`,
  so two rounds of the same condition differ while the whole session still
  replays deterministically in a test.
- `.tok` became `inline-block` so a transform applies. Word gaps still render as
  real separators.

## Notes

`reducedMotion` now threads from the client's `matchMedia` through the event into
the reducer and on to `mangle`. Later conditions with motion should read it the
same way rather than checking the media query themselves.
