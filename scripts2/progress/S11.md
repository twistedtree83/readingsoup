# S11 — Sim harness: headless N-participant sessions

Issue: #34 · Branch: `main` · Status: **shipped**

## What shipped

`scripts/sim.js` — spawns its own server and drives full sessions at 1, 2, 5, 8
and 20 participants, with a configurable proportion joining as observers.
Simulated participants hold a token exactly like a phone does, so disconnect and
reconnect are real rather than mimed.

```
bun run sim
bun run sim -- --sizes 2,20
bun run sim -- --url http://localhost:8787 --keep
```

## What it asserts

- Everyone reaches the roster and the headcount matches.
- **The roster carries no role**, and the host view carries no role-split count.
- **Nobody can see anyone else's role.** A participant's own role is legitimately
  in their own view; what must never appear is another person's.
- A locked phone keeps its roster place, the headcount drops while away and
  recovers on return, and reconnection by token restores name and role.
- **No non-reader has ever received passage content**, checked across every view
  every simulated participant has accumulated — not just the final one. Inert
  until S12 lands rounds, and a tripwire that costs nothing until then.

## Two bugs the first run surfaced

1. **My own role assertion was wrong.** It flagged observers for seeing their own
   role, which is correct behaviour — they chose it. Rewritten to count
   mentions against the participant's own role, and to check no other observer
   is nameable from their view.
2. **Room state accumulated across sizes** — 36 people on a 20-person roster.
   Disconnected participants are deliberately never removed (phones lock every
   round) and there is no session reset until S22, so a shared server carried
   every previous size's people into the next. Each size now gets a fresh room.

The second is a real product gap wearing a test costume: until S22 there is no
way to clear a room. Isolating the harness is the right fix for now, but S22
should not be skipped.

## Proving it has teeth

A check that cannot fail is worthless, so the roster rule was deliberately broken
— `role` added back onto roster entries — and both layers caught it
independently: the harness by observation (`roster leaks a role`) and the unit
suite by construction (two named tests). Then reverted, 106 green.

## Notes

The harness is the integration test and is not itself unit-tested. It boots one
server per size, which costs about a second each and buys complete isolation.
