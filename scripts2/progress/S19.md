# S19 — Group-size modes and the silent solo fallback

Issue: #42 · Branch: `main` · Status: **shipped**

## What shipped

The facilitator presses one button — **Start** — and the shape of the session
falls out of how many people are actually playing.

- **6+ → group.** Silent round, then spotlights capped at eight.
- **2–5 → small.** No silent round at all: straight to rounds, `ceil(6 / n)`
  each capped at three, so the room still meets all six barriers between them.
- **1 → solo.** The self-paced tour, silently.

## The edge case this slice exists for

Two people, one of whom chose to observe, leaves one active participant. The
session falls back to solo **and nothing anywhere says why**.

This is where invisibility is hardest, because there is only one other person in
the room. The test that matters is not "no error message" but **indistinguisha­
bility**: the host view for *one participant and one observer* and the host view
for *one participant alone* are asserted to have the same phase, the same mode,
and the same set of keys. Every view is scanned for "opted", "fallback", "not
enough", "waiting for", "only one", "too few" — nothing may appear on any screen
that appears only because somebody opted out.

The observer's own phone knows its own role, which is legitimately theirs.
Nobody else's screen learns it, and no emitted effect at any size carries a role
at all — asserted over a full round, with cards played, at 2, 3, 6, 8 and 20.

**No observer cover in the fallback.** [[S13]] gives observers a clean passage
during the silent round because a person sitting with nothing to do discloses
through body language what the app is keeping private. That argument does not
transfer here: at one active participant there is no room to disclose *to* — the
only other person present is head-down on their own tour. So the privacy rule
stays absolute rather than exempting a second phase, which is what [[S13]]'s
ledger warned against. If a session of two turns out to leave the observer with
nothing to look at for five minutes, that is a product call, not a runner's.

## Decisions taken

- **Mode is derived, never chosen.** `START_SESSION` reads the active count and
  routes. A facilitator who has to notice the headcount and pick a shape is the
  moment a small room gets it wrong.
- **Solo fallback reuses the tour, not a copy of it.** With exactly one active
  participant there is exactly one tour and one round, so it uses the same
  `tour` / `round` / `reader` fields the standalone tour does — the same core
  behind a different transport, never a second implementation.
- **Eight is a group cap, and small rooms are not held to it.** Five people at
  two rounds each is ten, and that is correct: the cap exists so a twenty-person
  session ends before the room does, not to shorten a session of five. The round
  budget is now mode-derived, and `SET_SPOTLIGHT_COUNT` clamps to it — a planned
  number of rounds the session cannot reach is a promise to the facilitator that
  it breaks.
- **The random draw now prefers whoever has read least**, not merely whoever has
  not read at all. That is what makes "three rounds each" true in a two-person
  room rather than merely intended; the old rule could deal a 4–2 split. Each
  participant carries a `rounds` count, which a tag-in also increments — the
  person who picked it up did read.
- **The projector states a small room's plan instead of offering one.** There is
  no spotlight chooser below six, because the number of rounds falls out of the
  headcount: *"2 rounds each — 16 minutes in all."*
- **The solo fallback gives the projector nothing to drive.** No draw button, no
  tappable roster: the tour is self-paced on one phone and interrupting it with
  a spotlight would be the facilitator overriding a person's own pace.

## Gaps this closes

- [[S15]] left the one-active-participant case open — an empty table, nobody
  holding a card, a barrier that could not be lifted. That configuration is now
  the solo tour, where the reader holds the whole deck themselves.
- [[S16]] inherited the same case. Same resolution.

## Verified

236 unit tests: mode selection at 1, 2, 3, 4, 5, 6, 8 and 20; `ceil(6/n)` capped
at three at every small size; a three-person room running all six of its rounds;
a two-person room across four seeds where neither participant repeats a barrier,
both do exactly three, and the pair meets all six between them; the full deck at
2–5 and three cards at 6+; the fallback starting the tour, finishing in the
catalogue, and being indistinguishable from a one-person room on every screen.

Harness green at 1, 2, 5, 8 and 20, asserting the mode START_SESSION chose at
each size and scanning every screen for anything that explains the group size.
In the browser at 560px: the host view stacked into a narrow column with nothing
overlapping, the room code legible, and the small-mode plan stated rather than
offered.
